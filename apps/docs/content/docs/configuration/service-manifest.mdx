---
title: Service Manifest
description: Service pulumix.yaml configuration
---

Each service has a `pulumix.yaml` manifest defining its metadata and stack-specific configuration.

## Full Example

```yaml title="services/my-api/pulumix.yaml"
metadata:
  name: my-api
  version: 1.0.0

build:
  context: root
  dockerfile: services/my-api/Dockerfile

stacks:
  local:
    replicas: 2
    baseDomain: '127.0.0.1.sslip.io'

  production:
    replicas: 10
    baseDomain: 'api.company.com'
```

## Fields

### `metadata`

Service identification.

| Field | Required | Description |
|-------|----------|-------------|
| `name` | Yes | Service name (lowercase alphanumeric with hyphens) |
| `version` | Yes | Semantic version |

### `build`

Docker build configuration. Optional — only needed when the build context differs from the service directory.

| Field | Default | Description |
|-------|---------|-------------|
| `context` | `.` | Build context (`root` for project root, `.` for service directory, or relative path) |
| `dockerfile` | `Dockerfile` | Path to Dockerfile relative to build context |

```yaml
build:
  context: root
  dockerfile: services/my-api/Dockerfile
```

### `stacks`

Per-stack configuration. Each key matches a Pulumi stack name. Values are passed to your `pulumix.ts` via `ctx.config`.

```yaml
stacks:
  local:
    replicas: 2
    baseDomain: '127.0.0.1.sslip.io'

  production:
    replicas: 10
    baseDomain: 'api.company.com'
```

Access in `pulumix.ts`:

```typescript
const replicas = ctx.config.replicas as number
const baseDomain = ctx.config.baseDomain as string
```

## Minimal Example

```yaml title="pulumix.yaml"
metadata:
  name: my-service
  version: 1.0.0

stacks:
  local: {}
```
